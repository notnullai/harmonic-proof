# Pontex Machine Health: re-run our benchmark yourself

Pontex Machine Health publishes a benchmark of its edge detection method on
four public vibration datasets: when it alarmed, how long before the failure,
how many false alarms it raised while it learned the machine's normal, which
failure it named, and when a classical 3-sigma RMS alarm would have fired on
the same data. This repository lets you re-run every one of those per-run
numbers on your own copy of the original datasets, and check our published
answers against what our service gives you.

The detection method itself is not published: it runs on our verify service.
You download each dataset from its original publisher, convert one run's
files with `verify.py` (plain numpy; the conversion is the whole of that file),
upload them with a key we issue, and the service runs exactly the method that
produced the published table and answers with the same per-run record. The
runner prints your answer next to the published one, pass or fail.

## What is reproduced

Every row of the published per-run table, 41 rows from 21 uploads:

| Dataset | Uploads | Rows | What each row holds |
|---|---|---|---|
| NASA IMS | 4: test 2 bearing 1, test 1 bearings 3 and 4, test 3 bearing 3 | 4 | detection time and lead, commissioning false alarms, names right/wrong per alarmed reading, 3-sigma comparator |
| XJTU-SY | 15: every bearing, both accelerometers | 15 | the same, per bearing (caught when either sensor alarms) |
| CWRU | 1: the 3 baseline records, the held-out 3 hp record, 6 fault records | 7 | the same; the baseline is learned once, each record replayed after it |
| Real gearbox (OpenEI) | 1: all 20 records | 15 | 5 held-out healthy loads, 10 broken-tooth loads |

A row passes only if every field matches the published one exactly
(`expected.json`, generated by our benchmark runner, never typed by hand).

## What is not reproduced here (yet)

Be as sceptical of these as of anything you cannot re-run:

- **MaFaulDa and Paderborn held-out false-alarm counts** and the **MCC5-THU
  (Tsinghua) gearbox figure, "32 of 120" trusted fault records alarmed**.
  They come from separate evaluation scripts, not from the benchmark runner
  this service wraps, so they are not served yet.
- **MFPT and FEMTO figures** quoted in our write-ups (for example the
  comparator's lead on MFPT faults).
- **Totals and summaries** built on top of the rows (for example "0 false
  alarms in 14,528 commissioning readings"): you can add them up from the
  rows yourself, but this runner only checks rows.
- **Anything about the method's footprint or speed on a controller**
  (memory, timing, determinism across platforms). This service checks
  results, not how they were computed.
- **Claims in pitch material** that are not one of the rows above.

## What a pass does and does not prove

A pass proves the published numbers are what our method gives on the public
data you downloaded: nothing in the table was hand-edited or computed on a
different copy. It cannot prove the service is not looking answers up. Test
that: change the data (scale a run, cut it short, swap two records' files)
with `--convert-only`, upload it yourself, and see the answers move. Every
answer names the build (git commit) that produced it and the SHA-256 of each
trained network it loaded; the runner flags an answer whose networks differ
from the ones the published table was computed with.

## Steps

1. **Get a key.** Ask us at contact@khalm.ai; it comes with the service's address.
2. **Install** Python 3.10 or later, then `pip install numpy scipy`.
3. **Download** the datasets from their publishers (about 1.1 GB for IMS,
   4.4 GB for XJTU-SY, 53 MB for CWRU's ten records, 37 MB for the gearbox):

   ```
   python download.py --data ./datasets
   ```

   Each file is checked against the SHA-256 of our copy. IMS and XJTU-SY
   are archives that need 7-Zip and a RAR reader; the script prints the
   commands. XJTU-SY is distributed only through file-sharing links on the
   authors' page, so fetch its six parts by hand, then run the script again
   to check them. Then confirm the unpacked file counts:

   ```
   python download.py --data ./datasets --check
   ```

4. **Verify:**

   ```
   python verify.py --server <address> --key <your key> --data ./datasets
   python verify.py ... --only cwru/all,gearbox/all       # the two quick ones first
   python verify.py ... --save answers.json                # keep every answer
   ```

   Converting reads every snapshot file; the large IMS and XJTU-SY runs take
   minutes to convert and up to about 15 minutes each to run on the service.

## What is sent

`verify.py` sends only what the method reads, as numpy arrays in one
deflate-compressed `.npz`, uploaded in 16 MiB parts:

| Dataset | Per upload |
|---|---|
| IMS | the run's one bearing channel, float32, the first 20,480 rows of each snapshot file, and the file names (time stamps) |
| XJTU-SY | both accelerometer columns, float32, the first 32,768 rows of each file, and the file numbers |
| CWRU | each record's drive-end signal (float64, as stored) and its RPM value where the file holds one |
| Gearbox | column 0 of each of the 20 tables, float64 |

Upload sizes, measured: see the table at the end of this file.

**Unpack XJTU-SY with RARLAB `unrar`**, which reads the six parts as one
set. Unpacking each part on its own (as Windows `tar` does) damages the five
files that span two parts (`37.5Hz11kN/Bearing2_3/358.csv`,
`40Hz10kN/Bearing3_1/966.csv` and `1832.csv`, `40Hz10kN/Bearing3_2/2317.csv`,
`40Hz10kN/Bearing3_4/1105.csv`); `download.py check` and `verify.py` both
refuse a damaged file. Every snapshot file is used.

## The datasets: sources, licences, citations

No data is redistributed here. Use each dataset as its publisher allows.

- **NASA IMS bearing data.** NASA Prognostics Data Repository, data set 4
  ("Bearings"), `https://phm-datasets.s3.amazonaws.com/NASA/4.+Bearings.zip`.
  Listed on data.gov as a U.S. Government Work (public domain). The data were
  donated by the University of Cincinnati's Center for Intelligent
  Maintenance Systems (IMS); please acknowledge the repository and the
  donors: J. Lee, H. Qiu, G. Yu, J. Lin, and Rexnord Technical Services,
  "Bearing Data Set", IMS, University of Cincinnati, NASA Prognostics Data
  Repository, NASA Ames Research Center.
- **XJTU-SY bearing data.** `https://github.com/WangBiaoXJTU/xjtu-sy-bearing-datasets`
  (download links to the authors' site and file-sharing services). No licence
  file; the authors state the data are public for validating prognostics
  algorithms and ask for a citation: B. Wang, Y. Lei, N. Li, N. Li, "A Hybrid
  Prognostics Approach for Estimating Remaining Useful Life of Rolling
  Element Bearings", IEEE Transactions on Reliability, 69(1), 401-412, 2020.
- **CWRU Bearing Data Center.** `https://engineering.case.edu/bearingdatacenter`
  (records 97, 98, 99, 100, 105, 118, 130, 209, 222, 234). No licence or terms
  are stated on the site; cite the Case Western Reserve University Bearing
  Data Center.
- **Gearbox Fault Diagnosis Data.** OpenEI submission 623,
  `https://data.openei.org/submissions/623`, CC BY 4.0.
